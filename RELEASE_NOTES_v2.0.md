# Release notes, version 2.0

Version 2.0 of the matrix-based active and reactive power flow contribution methods (`apfc.m`, `rpfc.m`). All comparisons below are with the archived version 1.0 and its results (`paper_results/`, unchanged in this repository). Version 2.0 was validated under Octave 11.1.0 with MATPOWER 7.1 (with the stand-in table functions of `tests/octave_shims/`); nothing was run in Matlab.

## Changes in behaviour against version 1.0

1. **Labels of the Case-3 source columns (RPFC).**
   - **What changed:** branches that inject reactive power at both ends give two source columns each (`E_i_j_f`, `E_i_j_t`). In version 1.0 their data were stored in a different order from their names, so with more than one such branch the column names did not match the data.
   - **Effect:** the names now match the data, and the values are equal to version 1.0 after the version 1.0 names are assigned in data order.
   - **Cases affected:** case9 (3 such branches) and case118 (13). Largest difference by position: 14.9553 Mvar (case9) and 199.6688 Mvar (case118). Case1 has one such branch and is unchanged.
2. **Negative reactive demand is a source (RPFC).**
   - **What changed:** a bus with negative reactive demand is now a source (column `D_b`), as in the earlier iterative method. In version 1.0 it was ignored, so its injection was spread over the upstream sources; where the bus had no other inflow, the downstream rows were wrong, without any error.
   - **Cases affected:** case14 (bus 4): 222 cells differ, by up to 1.9447 Mvar, and there is a new column `D_4`. In a synthetic test case without other inflow at the bus, version 1.0 gave rows wrong by up to 22.49 Mvar.
3. **Negative active demand and negative generation (APFC).**
   - **What changed:** a bus with negative active demand is now a source (column `D_b`), and a generator with negative output is a demand (row `G_b`). In version 1.0 negative demand was ignored, and a generator with negative output was kept as a source with negative output.
   - **Cases affected:** none of the version 1.0 test cases. In a synthetic test case, version 1.0 gave differences of up to 40.00 MW.
4. **Transformer-shunt demands of Case-2 branches (RPFC).**
   - **What changed:** a branch that consumes reactive power at both ends is replaced by its two terminal demands (rows `C2_b`), which already contain its shunt power. Version 1.0 also created inductive transformer-shunt demands (`Tf_b`, `Tt_b`) for such branches, counting that power twice. They are no longer created, as in the earlier iterative method.
   - **Cases affected:** none of the version 1.0 test cases. In the newly added case24_ieee_rts, the two removed rows held 56.64 Mvar.
5. **Unique labels.** A label that would repeat gets the suffix `_2`, `_3`, ...:
   - parallel branches in APFC (case118: 7 pairs, 14 rows; tap_loop: 1 pair, 2 rows);
   - demand rows in RPFC (case118: 5 rows; case14: 1 row);
   - generators at the same bus (`G_22`, `G_22_2`, ...; case24_ieee_rts), where repeated names would make `array2table` fail in Matlab.
6. **Positive active demand** is now PD > `opts.tol` (was PD > 0). No test case has a demand in (0, 1e-6].
7. **A power flow that does not converge** is now an error (`pfc:runpf:notConverged`); version 1.0 continued without a message.

## New features

- **Options:** `apfc(casedata, opts)` and `rpfc(casedata, opts)`, with `tol` (default 1e-6), `tol_div` (default 1e-9), `write`, `solved` and `name`. `casedata` may also be a case struct, or a solved case struct (with `solved = true`, `runpf` is not called). The defaults reproduce the behaviour above. Every threshold literal is replaced by `tol` or `tol_div`.
- **Diagnostics:** a third output `diag`, with sizes, non-zeros, sparsity, `condest`, the attenuation range, removed, flipped and converted elements, acyclicity, the spectral radius, the warnings, and the branches with a negative series flow.
- **Validity checks (`pfc_checks.m`):** acyclicity (Kahn's topological sort), the spectral radius for cyclic digraphs, the attenuation range, and the inflow guard, with identifiers `pfc:...`. They fall into errors, warnings, and information recorded in `diag` only; see the README.
- **Guard against a negative to-end shunt self-term:** error `pfc:rpfc:negativeSelfTerm` if a self-term is below `-tol_div`. It cannot occur for a valid carrier (the self-term equals Qt - aQ*Qf) and changes no result.
- **Sparse construction:** N, A and B are built with `spdiags` and `speye`, so they are sparse in Matlab as well (not verified in Matlab).
- **Negative reactive attenuation** is recorded in `diag.negative_series_flow`. It occurs in standard cases (case14, case24_ieee_rts, case118) and leads to some negative contributions; the README has the table.

## New and changed files

- New: `pfc_checks.m`, `cases/case24_ieee_rts.m`, `reference_results/`, `tests/` (unit tests, comparison tools, synthetic cases, Octave stand-ins, `tests/matlab_check.m`), `RELEASE_NOTES_v2.0.md`.
- Changed: `apfc.m`, `rpfc.m`, `batch_solve.m` (case24_ieee_rts added), `README.md`, `CITATION.cff` (version 2.0; the DOI must be added after the Zenodo version exists).
- Unchanged: `paper_results/` (the results of version 1.0) and the other case files.

## Compatibility

- `apfc(casedata)` and `rpfc(casedata)` work as before, and write the same files.
- The result tables differ only as listed above.
- Code that relies on repeated labels, or on the version 1.0 order of the Case-3 columns, must be adapted.

## Removed files

Two stray files of version 1.0 are removed from `paper_results/`: `case14.m_apfc.csv` (a byte-identical copy of `case14_apfc.csv`) and `case1a_rpfc.csv` (no matching case file). Both remain in the archived version 1.0.
